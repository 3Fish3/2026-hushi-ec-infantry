# 步兵 main 小陀螺方向偏移分析

分析基线：`main@0d0597e18ab52687fd2398dd52a059c8a5c596ac`。

> 历史分析说明：本文仅针对上述固定提交，不代表后续 `tzh` 分支的现状。后续分支状态与修复记录见 [2026-11-15 tzh 修复记录](../../docs/handoffs/2026-11-15_tzh-sweep-fixes.md)；下文保留当时的分析结论与验证边界。

问题描述：小陀螺持续旋转后，前进方向偏离当前枪管方向，退出小陀螺后仍然偏。截图所附文件名为 `gxnu_hushi_ec.zip`；截图本身不能证明车辆当时运行的是当前 `infantry/main`。

本文汇总源码审查、已有测试与记录核查、原生合成复现和浮点数值核算。**源码和部署配置未修改，未操作硬件。**此前临时生成的复现源文件及独立可执行文件已按要求撤回，本次只新增此文档。

## 1. 结论与适用范围

当前最需要解决的是：**用于底盘方向转换的云台机械角，可能在长时间运行或参考恢复后失去准确性，却仍被当作有效方向使用。**

已经查清的两个软件机制：

1. **连续角使用 `float` 逐帧累计。**在合法位置反馈序列下，累计加法的舍入误差可以显著增长；停止旋转后，已有误差不会自动消失。
2. **反馈超时清空累计角，重连直接从窗口内读数恢复有效。**若此前已跨过反馈窗口，会丢失累计窗口信息；在当前 25 rad 周期假设下，这会留下持续方向偏角。主控重启时也存在首帧参考不完整的问题。

同时必须保留三个边界：

- **正式 APP 默认尚未启用遥控/键鼠底盘运动。**`deployment_mapping()` 的底盘平移、小陀螺及键盘平移速度均为零；只配置了 yaw 操纵速率。上述问题是在启用相应操纵配置后需要面对的控制链问题。
- **25 rad 仍是软件展开假设。**PMAX 为 12.5 只证明编码映射范围，尚不能证明这台电机的 MIT 状态位置确实以 25 rad 回绕。
- **尚未确认截图实车的具体根因。**需要对应当时固件、实际配置及连续原始反馈；合成复现不能反过来证明硬件假设。

旧工程把 25 rad 映射成四整圈的换算已被当前 main 移除。正常反馈下的坐标转换、普通/小陀螺切换和四轮解算，未发现重复旋转或持续沿用旧平移方向的错误。

## 2. 机械角如何影响前进方向

完整相关链路如下：

```text
CAN 接收时间戳和 MIT 位置编码 p16
    → 按 PMAX 解码为窗口内原始角
    → 连续角展开
    → 减机械零位，得到云台相对底盘的关节角
    → 将遥控/键鼠平移指令从云台系旋到机体系
    → 四轮逆运动学与统一比例限速
    → 各轮速度环及 CAN 电流输出
```

IMU 另行用于云台世界航向估计和角度/速度双 PID。`infantry_cycle.cpp` 先保存机械关节角，再把提供给云台操纵映射器的角度替换为 IMU 世界航向；底盘转换保留原机械角。

设底盘世界朝向为 β，枪管相对底盘的真实机械角为 q，软件采用的角为 q̂。在平地、机械标定正确且四轮能够跟踪指令的条件下，前推对应：

```text
前进的世界方向 = β + q̂
枪管的世界方向 = β + q
前进偏离枪管的角度 = wrap(q̂ − q)
```

因此，机械角误差会直接变成前进方向误差。纯 IMU 航向漂移可能使枪管相对地面慢慢转动，但只要机械角正确，前进指令仍会跟着当前枪管变化；两种“偏”不能混为一谈。

普通模式与小陀螺共用同一次平移旋转，小陀螺增加底盘自转速度 `wz`。退出小陀螺不会重建机械角或校正零位，所以已有机械角误差会继续保留。

此方向契约适用于本地遥控/键鼠。主机协议的 `PlanarTwist` 是机体系指令，直接进入应用层；主机发送正 `vx` 表示底盘自身前方。

## 3. 连续运行：单精度累计为何会产生持久偏差

### 3.1 实际计算过程

`InfantryExecutor::dm_continuous_position()` 执行以下运算：

```text
delta = 当前 raw − 上一帧 raw
delta 超过正半窗：减去一个窗口
delta 小于负半窗：加上一个窗口
accumulated = accumulated + delta
```

`last_raw` 和 `accumulated` 均为 `float`，`delta` 也是 `float`。已有 ARM 编译产物中的对应运算使用 `vsub.f32`、`vadd.f32` 和单精度存储，确认累计确实在单精度域完成。

单精度浮点数具有有限有效位数。累计角增大后，相邻可表示数的间隔也增大；每帧小增量加入较大累计角时产生的舍入误差，会沿后续累计保留下来。

### 3.2 一个局部算术例子

在已经跨过 21 个 25 rad 窗口、累计角约为 525 rad 时，取合法反馈变化：

| 项目 | 数值 |
|---|---:|
| p16 | 32768 → 32773 |
| 解码 raw | 0.000190737774 → 0.002098115627 rad |
| 单精度 delta | 0.001907377853 rad |
| 累计角实际增加量 | 0.001892089844 rad |
| 本次少加 | 约 0.000015288 rad |

525 rad 附近的单精度相邻数间隔约为 `0.0000610352 rad`。上述增量不能无误差地加入当前累计角。在这个局部序列中连续增加 1000 次，累计角相对“整数窗口数 × 25 + 当前原始角”偏约 0.876°。

误差的符号和增长速度取决于输入序列及累计角所在区间，不保证始终单调增长，也不存在已经验证的统一“运行多少秒就会偏”的阈值。

### 3.3 排除编码分辨率和三角函数的影响

为隔离累计算法，使用以下合法 p16 合成序列：

```text
p16(i) = (32768 + 5 × i) mod 65535
N(i) = floor((32768 + 5 × i) / 65535)
基准角 = 25 × N(i) + decode(p16(i))
```

当前算法与基准消费同一份解码后 raw；基准的窗口计数由构造序列明确给出。该序列用于证明软件数值行为，不宣称真实电机会按此序列输出。

逐步 IEEE float32 内存核算结果：

| 有效更新次数 | 基准角 / rad | 当前单精度累计 / rad | 额外累计误差 |
|---:|---:|---:|---:|
| 10,000 | 19.073967934 | 19.073921204 | −0.00268° |
| 50,000 | 95.369077682 | 95.367866516 | −0.06939° |
| 100,000 | 190.737964630 | 190.735305786 | −0.15234° |
| 150,000 | 286.106851578 | 285.956115723 | −8.63653° |
| 300,000 | 572.213511944 | 570.556579590 | −94.93523° |

对照结果：

- 在这个序列的列出采样点，将完全相同的 float delta 改用双精度求和，与基准一致。
- 只在最后把终点基准角转成 float，误差约为 −0.000628°，远小于逐帧累计误差。
- 两种计算共用相同的原始编码及解码结果，因此表中差值不能归因于编码量化。

这证明本例的大误差形成于累计加法，进入 `sin/cos` 前就已存在。最后再取模只能改变角度表示范围，不能恢复已经丢掉的数值信息。

上述结果属于数值层验证，不是新做的固件端到端测试或实车测量。更新次数不能直接换算为实车时间。此前“2 rad/s、1 kHz、5 分钟约 50°”是另一特定输入算例，应以明确输入条件引用，不应作为车辆运行预测。

### 3.4 为什么退出小陀螺后仍偏

当相对位置不再变化时，`delta = 0`，已经算偏的 `accumulated` 保持不变。普通模式继续用它旋转平移指令，因而偏差持续存在。单纯切模式、把 `wz` 归零或重新调世界稳向 PID，都不会恢复累计过程中丢失的精度。

## 4. 失联、启动和恢复：收到新帧不等于找回机械参考

### 4.1 超时重连的具体时间线

前提：MIT 反馈确实按 25 rad 回绕；机械零位为 0；底盘操纵已启用；其他输入有效。

| 阶段 | 机械累计角 | MIT raw | 软件行为 |
|---|---:|---:|---|
| t = 1000 ms，正常 | 25.3 rad | 0.3 rad | 已展开为 25.3 rad，方向正确 |
| t = 1020 ms，健康检查观察到反馈过期 | 不变 | 无新帧 | 清空展开状态，正常本地路径撤销平移意图 |
| t = 1021 ms，恢复首帧 | 仍为 25.3 rad | 仍为 0.3 rad | 用 raw 初始化为 0.3 rad，立即恢复机械参考有效 |
| 切回普通模式 | 不变 | 不变 | 平移继续使用错误的 0.3 rad |

DM 反馈有效期为 20 ms，判断条件是 `age < ttl`，所以达到 20 ms 即过期。

恢复时丢失 25 rad，约等于 1432.394°；它与四整圈 1440°相差约 7.606°。在此正向示例中，前进方向产生约 +7.606° 的偏差。一般丢失 N 个窗口时，误差是 `wrap(−25 × N)`，符号由丢失方向决定。

此前原生 C++ 合成复现复用了现有 Rig 和当前应用库：连续转四圈时方向误差小于 0.03°；仅中断 DM 反馈 30 ms 后，恢复时偏约 −7.62°，切回普通模式仍保留。该复现采用非零合成操纵配置及 25 rad 回绕假设，不能当作默认部署固件的实车复现。临时复现文件已撤回，不作为当前仓库新增回归测试。

### 4.2 根本问题是恢复时错误地宣布有效

正常本地路径在失联期间能够撤掉平移意图。问题发生于恢复时：

1. 展开器失去累计窗口信息。
2. 新鲜帧只能提供窗口内 raw。
3. 软件仍减去原机械零位，并把结果标为有效机械角。
4. 下游没有信息判断这个角度已经换了基准。

DM 超时清累计及自动恢复没有同步调用应用层机械参考失效接口，机械参考代次也不会因此更新。云台可以重新从 IMU 捕获世界航向目标，但这无法补回底盘所需的机械相位。

### 4.3 四种情况需要分别判断

| 情况 | 当前处理及风险 |
|---|---|
| 控制循环持续运行，某次健康检查看到反馈年龄 ≥20 ms | 清展开器，重连存在上述累计信息丢失 |
| 控制任务暂停，恢复后先收到新帧 | 先收 CAN 再做健康检查，未必执行超时清零；不能把任意 20 ms 帧间隔都等同于 reset |
| 两次实际展开之间运动超过半窗口 | 只凭首尾差值可能选错连续分支；设备接收保留最新值，展开并非逐个接收帧执行 |
| 主控重启，或电调重启并改变位置原点 | RAM 累计状态可能丢失，或新 raw 被当成普通运动；电调原点是否改变取决于设备实际行为 |

如果周期确为 25 rad，同一 raw 可以对应 `raw + 25N`。由于 25 不是 2π 的整数倍，这些候选值对应的枪管朝向不完全相同。**一帧 raw 本身不足以恢复丢失的方向参考。**

因此，直接清累计后从 raw 继续会出错；无限期保留旧累计也不能解决长时间失联或电调重启。必须有足够依据确认参考连续，或重新建立可信参考。

## 5. 硬件语义、标定和其他机制的区分

### 5.1 PMAX 不足以证明反馈周期

MIT POS 的换算是 `raw × (2 × PMAX) / 65535 − PMAX`。当前配置 PMAX 为 12.5，软件随后将 `2 × PMAX` 当作展开周期。

仓库已有记录明确区分了两件事：编码范围已知；跨界后究竟回绕、饱和还是其他行为，仍需实测。实测 `p_m` 可以到 +19.86 rad，属于另一浮点寄存器读数，不能证明 APP 使用的 MIT 16 位 POS 具有相同跨界语义。

外部查阅的厂商署名 J4310 V1.1 手册说明了 POS 线性映射和可配置范围，未明确解决本设备 MIT POS 的越界行为。官方仓库存在更新版资料，但本次未成功解析该新版 PDF，不对其内容作结论。最终仍需匹配具体电机、固件版本和原始反馈。

### 5.2 症状与优先核查方向

| 症状 | 优先核查 | 区分依据 |
|---|---|---|
| 原始反馈正常，软件机械角逐渐偏离 | 单精度累计 | 离线按稳定基准重算，比较软件累计角 |
| 超时恢复时突然跳偏，之后保持 | 累计窗口丢失 | 跳变与反馈过期/恢复事件对齐 |
| 原始 POS 到边界后不动，但机构仍转 | 反馈饱和或位置语义不符 | 同时观察 POS、寄存器位置及实际机械运动 |
| 每次原始 POS 跨界时阶跃 | 回绕周期或展开方式不符 | 跳变与跨界时刻对应 |
| 从启动起就有固定偏角 | 零位或初始参考 | 不需要长时间旋转即可出现 |
| 偏差随相对转角变化，反转时趋势改变 | 符号或比例 | 对照真实相对角与软件关节角 |
| 枪管对地漂移，前进仍跟当前枪管 | IMU 零偏或稳向能力 | 机械方向转换仍一致 |
| 计算方向正确，实际轨迹偏 | 轮速跟踪、打滑、机械标定 | 与转速、负载、地面条件相关 |

当前配置的 yaw 机械零位为 0，跟随符号为 +1，四轮方向及布局仍有实车标定边界。记录中的传动约为 1:1、同向，不应仅因缺少独立外齿轮比例字段，就断言当前比例必然错误。

底盘倾斜且枪管带俯仰时，枪管世界水平投影与底盘切平面内方向也可能不同。这类差异随姿态变化，不能仅凭旋转时长解释累计偏差。

旧工程曾将 25 rad 强行映射成四整圈，比例约相差 0.531%。当前 main 已使用原生弧度展开，不再继承该换算。旧代码错误与当前累计/恢复问题应分别归因。

## 6. 为什么已有测试通过仍不能排除问题

| 已有覆盖 | 能证明什么 | 尚未覆盖什么 |
|---|---|---|
| 0、±90°、180°及相隔整圈的静态前进方向 | 基本坐标旋转及参考源选择 | 大累计角下的长期精度 |
| 正反跨一次 ±12.5 rad 窗口 | 在25 rad假设下，单次展开连续 | 真实设备跨界语义、多窗口长期误差 |
| 64秒世界稳向闭环 | 合成模型下航向控制与力矩链路 | 平移输入始终为零，未检查长转后的前进方向 |
| DM反馈超时禁止平移 | 失联时本地平移撤销 | 多圈后恢复、再次前进及退出小陀螺后的方向 |

已有4组相关主机测试在此前核查中通过，但这些覆盖不能替代上述缺失场景。

现有实板报告记录约 999.990 Hz 的采集频率，DM 反馈新鲜比例为 97.9748%；这是停止状态的采集结果，不等同于运动中每毫秒都有新的 DM 位置，也不能直接证明截图发生过掉线。未找到可用于对应截图的连续跨界及失联恢复原始记录。

## 7. 建议验证顺序与修正原则

本节为后续建议，未实施源码修改、烧录或动力试验。

1. **对应版本和配置。**确认截图车辆实际固件、操纵量程、机械零位，以及 MIT 的 PMAX 等参数。当前原样 main 默认底盘操纵量程为零。
2. **确认真实位置语义。**对同一段机械运动记录 MIT POS、`p_m/xout`、实际方位及时间，观察边界附近反馈行为；不要由模拟器的取模方式推定硬件周期。
3. **隔离数值累计。**使用同一段原始位置序列，对比现有累计角和有明确窗口依据的高精度重算结果。检查误差是否在不断线的情况下增长。
4. **检查参考恢复。**区分短暂反馈缺失、长间隔、主控重启和电调重启；观察恢复前后关节角及机械参考代次是否保持一致。
5. **检查完整方向契约。**在已确认的模型/配置下，覆盖持续旋转加前进、正反转、多圈后停止、超时重连和模式切换，直接断言前进方向相对枪管的误差。

修正设计应满足以下原则：

- 连续角的表示避免把微小增量反复加到越来越大的单精度总角上。可评估整数窗口计数配合当前原始角，或更高精度累计；最终方向相位的计算仍需考虑精度。
- 将“反馈新鲜”和“机械参考可信”分开。新的有效数据帧不能自动补回未知窗口数。
- 短间隔恢复只在连续性可证明时接续；依据应包括时间、可信运动界限及设备参考未改变的条件。无法唯一恢复时，应保持参考未知并明确重建。
- 坐标基准确实改变时，沿现有参考代次和目标失效机制同步通知消费者。

现有高频采集字段包含 MIT 解码位置、速度、反馈新鲜位、年龄和参考代次，但不包含软件累计关节角；累计关节角可在已有 `g_ec_infantry_yaw`/CAL 观测中找到。采集方案应先核对两路时间与有效性，不能只看“字段有数值”就认定参考正确。
