# J4310 Yaw 外齿轮小角度标定：工具与操作说明

## 1. 范围与交付状态

本工具识别 J4310 输出轴小齿轮与云台大齿轮直接外啮合的机械关系：

```text
theta_g = k * (theta_m - theta_m0)
omega_g = k * omega_m
```

云台从上往下看逆时针为正，枪管指向底盘正前方为机械 0°。`theta_m` 必须来自同一种已经确认的电机输出轴位置源，不能混入电机内部转子角。直接外啮合预期 `k<0`，实际系数由测量求出，不在配置中预设。

**本次完成软件准备，不是实车标定完成。** 没有真实测量 CSV，因此没有可回填的实车 k、零位或回差；IMU 安装与零偏标定不重做。未烧录、未使能电机、未发送运动命令或修改电机寄存器。

原始工具包位于 `/home/kekeyuyu/Downloads/infantry_yaw_small_angle_calibration.zip`，SHA256：`16e23d42dc170fbeb188a216c78d9f44d0fad09bf6d75a1016c3d25352a8f968`。已检查其中的方案、离线脚本和空模板；以原共同斜率/独立截距算法为基础集成，模板按本任务改为 10 点。

## 2. 源码调查：电机角与云台角

| 位置 | 源码事实与影响 |
|---|---|
| `include/ec/drivers/dm.hpp::decode_dm_feedback()` | MIT 反馈 D[1:2] 是 16-bit 位置编码，按 `POS / 65535 * (2*PMAX) - PMAX` 解码；速度/力矩为 12-bit。D[0] 低 4 位是节点，高 4 位是状态。PMAX 是编码映射范围，不证明回绕周期。 |
| `robots/infantry/app/infantry_execution.cpp::dm_continuous_position()` | 现有 `DmUnwrap` 用 `2*position_max_rad` 作为窗口，按半窗口判断跳变并累计。这是当前软件假设，设备跨界究竟回绕、饱和还是另有语义尚需实测。 |
| 同文件 `joint_feedback()` | DM 位置为展开的电机角减 `zero_offset_rad`，速度原样取电机反馈；**没有外齿轮 k 换算**。APP 的 CAL `joint`/SWD `joint_angle_rad` 因此不能直接当作本次独立云台量角真值或原生 xout。 |
| 同文件 `health()` | 使用同一展开器建立参考，失联后调用 `reset_dm_unwrap()`；不能仅凭重连一帧还原丢失的电机圈数。 |
| `robots/infantry/app/infantry_cycle.cpp::control()` | `main_joint` 来自执行器机械反馈；底盘平移使用 `R(chassis_follow_gain * main_joint)`。目前这个输入未校正外齿轮比。IMU 局部惯性航向另用于世界稳向，两种角不混用。 |
| `robots/infantry/app/infantry_config.hpp` | `DmSlot` 没有外齿轮比例字段；`JointGeometryConfig` 只有零位/范围。正式装配为 CAN1、命令/反馈 ID 均 0x005。 |
| `robots/infantry/capture/` | 原 legacy 候选是 CAN2、命令 ID1、反馈 Master ID0x011。新增可选 `infantry_yaw` 配置后按 CAN1/0x005、反馈 node5 采集，默认 legacy 保留。 |
| `boards/infantry_f407/tools/infantry_capture.py` | 已能显示 p_m(RID0x50)、xout(RID0x51)、PMAX(RID0x15) 与 MIT 原始 p16；新增人工齿轮标记及拟合 CSV 导出，不自动展开位置。 |
| `robots/infantry/host/infantry_raw.py` / 原始记录器 | 复用 ECRAW1 有界短窗。步兵采集角色改为按同一装配表记录 CAN1/0x005；CSV 导出保留 bus/can_id/dlc/data，旧角色默认映射不变。 |

参数读取只能发送 STD0x7FF、DLC4、`05 00 33 RID` 白名单请求；只读状态查询是 `05 00 CC 00`。应答须匹配 CAN1/0x005、回显电机 ID、RID、当前在途请求及 `<100 ms` 时限。未支持寄存器、无应答、迟到、NaN 和旧快照不会被当成有效零值。

## 3. 构建独立步兵采集镜像（不烧录）

以下命令均从仓库根 `infantry/` 运行，使用已有 ARM GNU、Ninja、项目 `.venv` 和本地 SDK：

```sh
cmake -S . -B build/infantry-yaw-capture-arm-Release -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_TOOLCHAIN_FILE="$PWD/cmake/arm-none-eabi.cmake" \
  -DARM_GNU_ROOT=/usr \
  -DEC_STM32CUBE_F4_ROOT="$PWD/build/deps/STM32CubeF4-v1.28.3" \
  -DEC_BUILD_INFANTRY_CAPTURE=ON -DEC_CAPTURE_INFANTRY_YAW=ON \
  -DEC_BUILD_INFANTRY_APP=OFF -DEC_BUILD_INFANTRY_S1=OFF \
  -DEC_BUILD_TESTS=OFF -DEC_BUILD_EXAMPLES=OFF \
  -DEC_FIRMWARE_ID=yaw-gear -DPython3_EXECUTABLE="$PWD/.venv/bin/python"
cmake --build build/infantry-yaw-capture-arm-Release --target infantry_capture -j4
```

产物：`build/infantry-yaw-capture-arm-Release/boards/infantry_f407/infantry_capture.elf/.bin/.hex`。链接后自动执行 `check_capture.py`，检查限定只读发送路径、禁止的执行器符号及镜像布局。默认 `EC_CAPTURE_INFANTRY_YAW=OFF` 仍构建 legacy 采集配置；不要混用同一构建目录的角色。

**烧录是另行人工确认的操作，本说明不提供自动烧录步骤。采集固件不能停车，也不会自动发 DM disable。** 切换前须按现有实际方式失能电机、固定底盘、支撑云台并确认物理急停。不能以刷入只读固件替代失能确认。

## 4. 串口连接与 GUI

### 两个固件角色的接口不同

| 角色 | MCU 串口 / 源码引脚 | 速率与工具 |
|---|---|---|
| 正式 APP | USART1：PA9 TX、PB7 RX；C 板外壳 UART2 | 921600；APP 客户端 / CAL；不能直接连接本采集 GUI |
| 独立 capture | USART6：PG14 TX、PG9 RX；C 板外壳 UART1 | **115200 8N1**；`infantry_capture.py` / 原始短窗工具 |

上述引脚已核对当前 `cubemx/infantry_s1/Core/Src/usart.c`，外壳接口说明见[接口与接线注意](接口与接线注意.md)。请以实物标识/板卡版本复核线序：串口适配器 TX→板 RX，RX←板 TX，GND 共地，电平匹配。不要沿用此前猜测的 PA10 或 PC6/PC7。

双 DAP 只读检查中，序列号 `332107148313` 的 SWD 成功读到 `0x2ba01477`；`332107148384` 的 CDC 在 `/dev/ttyACM1` 成功读取正式 APP 的 CAL 和 HELLO/status。**这证明当前 APP 的 USART1 链路可用，不证明切换后 USART6 已接通。** 开始采集前需人工把串口侧接到采集角色的 USART6，并使用稳定 by-id 路径，不能仅改波特率就假定兼容。USB 描述符不用于判断无线/有线状态。

人工确认已烧录上述采集角色、连线并供电后：

GUI 只发送既有分页快照请求，不接受任意 CAN 透传。若 profile 不符、协议版本不符或无应答，应先核对镜像、USART6 接线及实际电机 ID，不要发送 enable 或改寄存器来“试通”。`NO_REPLY` 可能是未支持、地址不符或超时，需要保留日志并核查，不自动切换位置源。

## 5. 人工小角度测量与记录

1. 固定底盘，轮子无动力，J4310 已失能且新鲜状态反馈为 disabled（状态 0）。**不要在使能状态强行反拖**；不能安全回驱则停止本方案。
2. 使用独立量角器/固定刻度或激光标定板测量云台角。IMU 只作交叉观察，不作唯一真值。
3. 先人工做 ±5° 预检，确认无机械干涉、反馈有效、不会漏掉电机圈数；齿比未知时进一步减小移动步长。不要硬顶机械限位。
4. 选定一种来源 `p_m`、`xout` 或 `mit_pos`，确认其物理含义与单位后整份数据固定使用。`mit_pos` 还需要新鲜、有效的 PMAX；GUI 仅映射 p16，不把 ±PMAX 当周期。
5. 正向：**−10 → −5 → 0 → +5 → +10°**。到首点之前按正向靠上同一齿面；每点独立量角、停稳、观察反馈稳定后勾选“已静止且读数稳定”，填写方向、实际角度、位置来源、机械标记与备注，再点“记录齿轮点”。每次记录后稳定勾选会清除。
6. 反向：**+10 → +5 → 0 → −5 → −10°**。反向首点同样按 reverse 方向预先靠上齿面再回到 +10°，不要把换向前的正向端点直接复制。若不能安全在行程内预加载该端点，缩小测量范围并记录实际角度，不越限；每方向至少 3 个不同角度。
7. GUI 会先刷新 DM 状态再刷新所选位置源/PMAX。只有新鲜失能反馈、有效位置和人工静止确认同时满足才写 `yaw_gear_sample`；失败留下 `yaw_gear_rejected` 和原因，原始页面/普通 mark 仍保留。各页并非同步采样。
8. `sampled_ms` 记录 MCU 收到该反馈/寄存器应答的时间，`age_ms` 加上 PC 页面老化；设备内部测量延迟未由这些字段保证。位置样本要求 `<500 ms`，不是机械精度阈值。
9. 出现编码跳变、重启、失联或回差异常时先停止记录，保留原始值。工具不猜周期、不恢复丢失圈数，跨 MCU 分段和混合来源不能一起导出拟合。

原始 JSONL 包括固件身份、ELF SHA256、接线标签、源寄存器位值/原始 CAN 字节、时间与有效性。字段 `turret_deg` 是**独立量角实际读数**，不是默认填目标刻度值。

## 6. 导出与拟合（全离线）

关闭 GUI 释放串口后，下面两步都不打开硬件：

```sh
.venv/bin/python boards/infantry_f407/tools/infantry_capture.py \
  --export-gear .tmp/yaw-gear/run-01.jsonl --csv .tmp/yaw-gear/measured.csv
.venv/bin/python tools/fit_yaw_gear.py .tmp/yaw-gear/measured.csv \
  --residuals .tmp/yaw-gear/residuals.csv
.venv/bin/python tools/fit_yaw_gear.py .tmp/yaw-gear/measured.csv \
  --json > .tmp/yaw-gear/report.json
```

输出文件必须新建，不覆盖旧记录。拟合 CSV 固定列：

```text
approach,turret_deg,motor_rad,source,sampled_ms,age_ms,valid,mark,note,data_kind
```

GUI 导出真实人工记录标记为 `REAL`；离线回归夹具明确为 `SYNTHETIC`。手填时可复制 `tools/yaw_gear_samples_template.csv` 到新的工作文件，空 `motor_rad` 不能运行成“标定成功”。旧三列文件仍可计算，但来源、时效和有效性缺失时只输出待复核结果。

拟合保留共同斜率 k、正反两个截距及零位，输出等效大/小齿数比、每方向斜率、云台侧回差、逐点预测/残差、RMS 和最大残差。拒绝空值、非有限数、无效或过期反馈、同方向重复角度及混合来源；不把正反点合成一个截距。

退出码：`0` 数学拟合完成（不表示可部署）；`2` 数据输入拒绝；`3` 已输出拟合但符号或连续性需复核。大于 π 的相邻电机角变化/超过 2π 的跨度只作为需复核迹象，不证明设备按 2π 回绕，也可能是较大机械减速比，必须结合连续原始记录确认。没有独立非拟合点验收时，报告 `deployable=false`。

### 可选：复用现有原始 CAN 短窗

此工具仍只观测，不控制电机。与 GUI 不同时占串口；rotation 模式会临时只读查询 DM 状态，不读位置寄存器，短窗冻结后恢复原读取调度：

```sh
.venv/bin/python robots/infantry/host/infantry_raw.py capture \
  --port "$SERIAL" --baud 115200 --profile rotation --duration-ms 200 \
  --output .tmp/yaw-gear/raw-01.sraw
.venv/bin/python robots/infantry/host/infantry_raw.py export \
  .tmp/yaw-gear/raw-01.sraw --output .tmp/yaw-gear/raw-01.csv
```

保留 `.sraw` 和同轮 GUI 的固件/配置身份记录；若需单独归档短窗，使用工具已有 `--metadata` 指定包含 `elf_sha256`、`profile=infantry-yaw`、CAN1/0x005、机械标记和来源的 JSON。短窗容量 512 条，满时提前冻结；它不是全程无损长日志。

## 7. 未来控制层接入建议（本轮不实现）

- 在配置中新增**可选**外齿轮标定结构，显式保存 `motor_to_joint_k`、电机侧 `motor_zero_rad`、反馈位置源/连续角约定和来源，未测时保持缺项。正反零位、回差作为标定结果保留，不随意平均。
- 在 `InfantryExecutor::joint_feedback()` 的 DM main_yaw 分支，通过一个统一适配函数输出 `k*(theta_m-theta_m0)` 和 `k*omega_m`；`health()` 的关节参考/限位也调用同一换算，原生电机反馈及原始采集仍保留电机坐标。
- `InfantryCycle::control()` 与底盘 `R(ψ)` 只消费已经换算好的云台关节角，不再额外乘 k，不把它藏进 `chassis_follow_gain`。
- 零位或比例变更需使旧关节参考与本地保持目标失效，沿既有 `set_joint_geometry()`、域参考代次和 `drop_held_angle()` 机制更新两侧；不能保留旧角坐标下的目标。
- 先验证电机真实回绕/饱和行为，再选择展开器。失联重连后的圈数参考不由一帧恢复；特别是外部 k 非整数时，错一圈电机角不等于云台整圈，不能按相位等价掩盖。
- IMU 世界航向链保持独立；力矩方向、速度环输出的电机侧单位和实际负载另行验证，本次不调整 PID/控制律，也不把 k 直接当作 PID 倍率。
